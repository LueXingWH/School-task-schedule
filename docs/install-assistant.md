# 便捷安装助手：自动准备，首次浏览器确认

1.5.0 提供单文件 `xiaoshijian-1.5.0-setup.exe`。可点击“浏览…”选择安装位置，也可直接输入路径；助手负责解压、校验资源、创建桌面入口和初始配置，普通用户不需要 Node、Python、终端或管理员权限。

本版还会将 `bridge/Xiaoshijian.Mcp.exe` 放入扩展目录，并为所选浏览器注册当前用户 Native Messaging 入口。MCP 接入默认关闭；需要时在设置页启用、生成配置交给本机 agent，详见 [MCP 指南](mcp-guide.md)。这不会修改其他客户端的配置。

界面按「品牌带 + 卡片 1（浏览器与安装位置）+ 准备按钮 + 卡片 2（浏览器首次加载四步）+ 检测结果卡 + 状态栏」排布，窗口 780×816、可滚动：四步指引是 2×2 的序号网格，管理页网址与“复制网址 / 打开扩展管理页 / 复制扩展路径 / 如何打开工作台”按操作顺序排在同一张卡里；准备文件时按钮下方出现进度条，状态栏分阶段说明正在解包校验还是放置文件。检测结果常显并带颜色区分（已加载为墨绿、停用或仅准备过文件为琥珀、未发现为灰）。

**它不是绕过浏览器的静默安装。** 当前未上架商店，Edge 首次加载仍需用户确认。普通用户点击商店“获取 / 添加”的完整分发方式，需使用开发者账号提交到 Microsoft Edge Add-ons 并通过审核；材料见 `store-submission.md`。

## 首次使用

1. 双击安装助手，默认选择 Microsoft Edge。“安装位置”可直接修改或点击“浏览…”选择文件夹；不修改时仍使用 `%LOCALAPPDATA%\Xiaoshijian`。填写后点击“准备安装并打开浏览器”，无需自己解压 ZIP。
2. 助手将全部资源放到所选位置的 `Extension` 子目录，创建桌面“校事笺”入口，并打开一个新的浏览器窗口。**助手不会替你写剪贴板**：点界面上的“复制网址”，到浏览器地址栏按 **Ctrl+V、回车**进入扩展管理页（Edge 为 `edge://extensions/`，Chrome 为 `chrome://extensions/`；网址也直接显示在界面上，可选中后 Ctrl+C）。
3. 打开“开发人员模式”开关——**它的位置两个浏览器不同，也是最容易找不到的一步：Edge 在扩展管理页的左下角（页面最底部），Chrome 在页面右上角**。打开开关后点“加载解压缩的扩展”，点助手的“复制扩展路径”（扩展路径也直接显示在界面上，可选中后 Ctrl+C），在文件夹选择窗口按 **Ctrl+V** 粘贴，再点“选择文件夹”。此目录是所选安装位置下的 `Extension` 子目录。
4. 校事笺首次加载会自动打开欢迎页，应用默认设置：截止日排序、未来 7 天截止视图、本地保存。点击收录即可使用，没有密钥或服务器配置。

以后双击桌面“校事笺”直接进入工作台；收录当前网页仍从浏览器工具栏的校事笺图标操作。桌面入口需在当初加载扩展的浏览器配置中打开，多配置用户请使用相同配置。

**已装过的自动识别**：助手启动和修改安装位置、切换浏览器时会自动检测，不再要求每次重新安装。检测读取两部分记录——浏览器各用户配置中已加载扩展的注册信息（`Preferences` / `Secure Preferences` 的 `extensions.settings`，含解压扩展的 ID、路径与启停状态），以及目标目录的 `install-receipt.json` 安装回执。**检测结果用界面底部加粗的“检测结果”一行明确显示**（已加载 / 已加载但被停用 / 仅准备过文件 / 未发现），状态栏同步给出版本、配置名、目录和建议动作；填写的安装位置与实际目录不一致时自动填回原目录。检测只读文件、不写浏览器数据；依据是浏览器正常退出时落盘的配置文件，浏览器正在运行期间的最新加载变化，要等它退出后才能被识别。

“打开扩展管理页”按钮在准备文件前也可使用，行为与上述相同：打开新的浏览器窗口并在状态栏给出操作指引。**助手只在你点“复制网址”或“复制扩展路径”时才写剪贴板，其余任何时候不覆写你复制的内容。**

「如何打开工作台」不自动跳转——实测部分环境下浏览器会拦截外部进程请求的工作台地址（用户反馈复现），因此点击后由状态栏直接给出操作指引：① 双击桌面“校事笺”快捷方式；② 点浏览器工具栏右上角的校事笺图标；③ 在扩展管理页点校事笺的“详细信息”，里面有工作台链接。若浏览器显示无法访问，说明当前打开的不是加载校事笺的那个用户配置：切换到加载扩展的配置（Edge 右上角头像可切换）后再试。助手检测到加载配置时，提示里会直接写明该配置名。

需要说明的边界：Edge/Chrome 会刻意丢弃外部进程通过命令行传入的 `edge://`、`chrome://` 等内部页地址（本机 Edge 156 实测：冷启动和热启动都只落到新标签页；`microsoft-edge:` 协议与 `--app=` 参数同样无效），早期版本曾用“打开新窗口后自动粘贴地址”绕过，但真实多配置环境不可靠，1.2.2 现改为显示网址、由用户复制粘贴进入；开发人员模式、加载确认和目录选择始终由用户在浏览器中亲手完成。

浏览时若选择磁盘或已有其他文件的文件夹，会自动使用其 `Xiaoshijian` 子目录，实际位置会回显在输入框中。直接输入时可使用任意名称的新目录或空目录；磁盘根目录、相对路径和非空的未管理目录会明确拒绝，避免混入或覆盖其他文件。

这里选择的是扩展程序的安装位置。EXE 的下载保存位置由浏览器下载设置决定，通知数据库仍由浏览器扩展存储管理，不随安装位置自动移动。

## 更新及已有数据

更新前先从旧工作台导出完整备份，并关闭校事笺工作台。再次运行新版助手时选择原安装位置；旧扩展文件保留到 `.previous-*` 子目录。在扩展管理页点击“重新加载”。同一目录对应的本地扩展 ID 保持不变，数据库中的通知、勾选和自定义设置继续保留。

从原先其他目录的 ZIP 版切换到助手目录，会改变未打包扩展的 ID。请在旧版导出备份，在新工作台的设置中恢复；不能声称两套目录自动共用数据库。旧文件副本不包含浏览器数据库，不能代替数据备份。

助手不修改浏览器 Preferences、不写浏览器强制安装注册表、不开放调试端口、不启动后台服务器、不设置开机启动。你仍可选择原 ZIP 手动安装方式。

## 文件与卸载

- 资源和准备记录：你选择的安装位置，默认 `%LOCALAPPDATA%\Xiaoshijian`
- 工作台入口：当前用户桌面 `校事笺.lnk`
- 旧扩展文件备份：安装目录下 `.previous-*`
- 通知数据库：由对应浏览器扩展管理，不在安装目录里。

卸载前导出完整备份，在 `edge://extensions` 移除扩展，再按需要手动删除助手准备目录和桌面入口。

安装助手为本地构建的未签名 EXE，签名检查结果为 NotSigned。Windows 可能要求确认来源。请仅使用可信来源的包并核对发布包中的 SHA-256；若不使用 EXE，可按原 ZIP 指南安装。

## 验证与范围

实际运行 EXE，在中文和空格路径准备文件，逐文件核对生产 ZIP；检查真实 Windows 快捷方式；在真实 Edge 和 Chrome 点击管理入口，验证浏览器新窗口打开、**系统剪贴板内容保持不变（哨兵断言）**、状态栏提示复制网址并写明开发人员模式开关位置，再按提示导航到真实管理页并截图；实际加载扩展、验证自动欢迎和默认配置、命令行入口；验证检测功能在全新配置无误报、加载并退出浏览器后能按 ID/版本/目录识别已装扩展；重复准备并重启后检查通知、勾选、自定义设置和原目录 ID 保留。测试使用独立目录和浏览器配置，不安装到用户日常配置。

支持本轮验证的 Windows 环境与 Edge 156 / Chrome 154；EXE 使用系统 .NET Framework，开发构建需要 Windows 自带的 C# 编译器。企业策略禁止侧载或禁用脚本快捷方式等环境不在本轮支持验证范围。
