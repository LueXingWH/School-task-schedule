# 更新参赛材料包

`npm.cmd run package:competition` 更新本地 `成果交付`，不会把参赛报名资料提交到 Git。先完成当前版本的业务验证和 PPT 更新，再执行组包。

## 输入与预检

- `release` 中当前版本的 Edge/Chrome ZIP、安装助手；两个浏览器 ZIP 必须同内容，manifest 版本与 `package.json` 一致。
- `test-results` 中当前版本通过的单元、核心、交互、识别、MCP、ZIP 安装恢复报告。
- 已核验的 `成果交付/.competition-build/update-<版本>/output/校事笺_<版本>_作品介绍_已核验.pptx` 和同级匹配其 SHA-256 的 `validation*.json`。PPT 保留10页、人员信息和原版式，版本、功能、测试数、实际界面需同步。
- 既有 `成果交付/参赛包_校事笺_2026`。报名表、汇总表、邮件草稿和赛事截图按原字节保留；旧 PPT 如果在核验后又被编辑，脚本停止以免覆盖新内容。

运行 `npm.cmd run package:competition -- --dry-run` 可以先查看版本、源代码提交、报告及保留文件清单，不会替换现有交付文件。正式组包前应先提交待交付的代码，源码 ZIP 来自 `git archive HEAD`，不包含未跟踪文件、依赖、构建缓存和个人资料。

## 输出与替换

脚本先在 `.competition-build` 中准备新包，更新应用、源码、PPT、使用文档和实际证据，检查 ZIP 内的每个文件并生成 SHA-256 清单。全部检查通过后才替换活动目录；旧目录、旧发布文件及旧参赛压缩包移到 `replaced-*` 本地备份中。替换过程中出错会尝试还原。

外层文件命名为 `自主研发应用_校事笺_参赛包_YYYYMMDD.zip`，日期使用北京时间。活动参赛包提供双浏览器通用扩展 ZIP；安装助手未复验全部 WinForms 按钮时，不将 EXE 或旧按钮记录加入参赛包。旧版 clean-build、setup 报告不会作为当前版本证据。

组包后若继续修改表格或其他材料，应重新运行组包，更新外层 ZIP 和哈希清单。脚本不填写未知身份信息，也不发送报名邮件。
